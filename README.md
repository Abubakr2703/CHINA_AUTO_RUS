# CHINA AUTO RUS

Windows-приложение для исследования и последующей русификации мультимедийных систем
китайских автомобилей. Первый профиль — **Changan Deepal S07 2026, китайская версия,
рестайлинг**.

> Статус: **Этап 3.1 — resources.arsc пересобирается и строки заменяются**.
> Проверено на F-Droid и NewPipe: пересборка байт-в-байт. Дальше — сборка APK
> и RRO-оверлей.

## Задачи MVP

1. Импорт файлов и папок с компьютера.
2. Анализ структуры, форматов и содержимого файлов.
3. Поиск и извлечение языковых ресурсов для перевода на русский.

Дополнительно: SHA-256, дерево файлов, отчёт анализа, сохранение оригиналов,
логирование ошибок.

## Стек

- Python 3.12+
- PySide6 (GUI)
- pytest, ruff, mypy (dev)
- SQLite — только если появится реальная необходимость

```
│   ├── arsc.py       # разбор бинарной resources.arsc

```

Пользовательские данные пишутся вне каталога установки:

```
%LOCALAPPDATA%\CHINA_AUTO_RUS\
├── reports\     # JSON- и Markdown-отчёты
├── logs\        # app.log и его ротация
├── settings\    # пользовательские настройки
├── profiles\    # свои профили автомобилей (JSON)
└── workspace\   # рабочие копии
```

Если `LOCALAPPDATA` отсутствует, используется `~/.local/share/CHINA_AUTO_RUS`.
Исходный код и ресурсы по-прежнему читаются из `PROJECT_ROOT`.

## Запуск

```bash
python -m venv .venv
.venv\Scripts\activate
pip install -e ".[dev]"

python -m china_auto_rus
python -m china_auto_rus --check
python -m china_auto_rus --profiles
python -m china_auto_rus --analyze "C:\path\to\dump"
python -m china_auto_rus --analyze "C:\path\to\dump" --no-hash
python -m china_auto_rus --analyze "C:\path\to\dump" --profile my-car-2025-cn
python -m china_auto_rus --strings "C:\path\to\firmware.bin"
python -m china_auto_rus --resources "C:\path\to\apk_or_res" --csv strings.csv
python -m china_auto_rus --resources "C:\path\to\apk" --translation-csv ru.csv
python -m china_auto_rus --check-translations ru.csv
pytest
ruff check .
mypy
```

`--strings` ищет печатные строки внутри файла, формат которого ещё не известен:
UTF-8, UTF-16 LE/BE, GBK. Показывает смещение, кодировку и текст, первыми —
строки с китайскими иероглифами. Это разведка: где в образе вообще живёт
китайский текст.

`--resources` собирает пары «ключ → текст → язык» из четырёх источников:

- бинарная `resources.arsc` внутри APK — разбирается без распаковки;
- XML-ресурсы Android (`res/values*/strings.xml`) — если дерево уже распаковано;
- бинарный AXML: `AndroidManifest.xml` и `res/**/*.xml` (layout, menu, xml),
  где текст лежит прямо в атрибутах (`android:text`, `android:title`,
  `android:contentDescription`);
- JSON-локали (`assets/lang/ru.json`, `i18n/zh-CN.json`).

`--csv` сохраняет результат в таблицу (UTF-8 с BOM, чтобы Excel не ломал
китайский). Составные ресурсы (массивы, стили, ссылки) пока не разбираются
и честно помечаются в отчёте.

AXML читается по содержимому, а не по имени файла: приложения с
обфусцированными путями (`res/0L.xml`) тоже разбираются. Ссылки
(`android:text="@string/…"`) пропускаются — их значения уже есть в ARSC,
поэтому одна и та же строка не попадает в шаблон дважды. Технические
атрибуты (права, имена классов, `layout_*`, анимации) отфильтрованы.

### Перевод

`--translation-csv` пишет шаблон `source,key,original,translation` — ровно то,
что нужно переводчику. Колонка `original` не меняется, в неё дописывается
только `translation`.

- оригинал берётся на китайском (`zh-CN`, `zh`, `zh-TW`), а если китайского нет —
  на языке по умолчанию; русский как оригинал не используется;
- одна и та же строка у разных ключей остаётся один раз: переводить надо
  уникальные тексты, а не все вхождения;
- ссылки, e-mail, имена пакетов и числа в шаблон не попадают — это не текст
  интерфейса.

`--check-translations` показывает прогресс и проверяет то, на чём обычно ломается
русификация:

| Код | Что значит |
|---|---|
| `empty` | перевод пустой |
| `cjk_left` | в переводе остались иероглифы |
| `placeholder_mismatch` | потерян, добавлен или изменён `%1$s` / `%d` |
| `brace_mismatch` | потерян `{0}` / `{count}` |
| `tag_mismatch` | потерян `<b>`, `<br>` или другой тег |
| `untranslated` | перевод совпал с оригиналом (предупреждение) |
| `newline_mismatch` | другое число переносов строк (предупреждение) |
| `too_long` | строка заметно шире оригинала (предупреждение) |

Код возврата `1`, если есть ошибки — удобно для скриптов и проверки перед
сборкой. Оригинальные файлы не изменяются: всё это работа с CSV.

### Профили автомобилей

Модель автомобиля — это данные, а не код. Логика анализа ничего не знает
про Deepal: марка, год и рынок приходят из профиля.

- встроенные профили — отдельные модули в `src/china_auto_rus/profiles/`
  (`deepal_s07_2026_cn.py` — один файл на модель);
- свои профили — JSON-файлы в `%LOCALAPPDATA%\CHINA_AUTO_RUS\profiles\`:
  правка кода и пересборка не нужны;
- при совпадении `id` побеждает встроенный профиль, чтобы личный файл
  не перекрывал проверенные данные.

`--profiles` показывает список, звёздочкой отмечен профиль по умолчанию.
`--profile ID` выбирает профиль для `--analyze`; выбранный профиль целиком
попадает в JSON-отчёт.

Пример своего профиля:

```json
{
  "id": "my-car-2025-cn",
  "brand": "Changan",
  "model": "CS55 Plus",
  "year": 2025,
  "market": "CN",
  "trim": "",
  "head_unit": null,
  "hardware_platform": null,
  "notes": "свой автомобиль"
}
```

Обязательные поля: `id`, `brand`, `model`, `year`, `market`. `id` — латиница
в нижнем регистре, цифры и `. _ -`. Неизвестные поля игнорируются, а битый
файл не мешает остальным: `--profiles` покажет его отдельной строкой.

Двойной клик или запуск без активации venv:

```bat
run.bat          :: GUI с консолью
run-silent.bat   :: GUI без консольного окна (pythonw.exe)
```

`run.bat` всегда использует `.venv\Scripts\python.exe`, поэтому не зависит от
того, какой `python` первым нашёлся в `PATH`. Если всё же запустить глобальный
интерпретатор, приложение не покажет traceback, а напечатает инструкцию и
вернёт код `2`.

В Git Bash (MINGW64) обратные слэши съедаются, поэтому пути пишем через `/`:

```bash
.venv/Scripts/python.exe -m china_auto_rus
source .venv/Scripts/activate    # после активации работает обычный python
./run.bat                        # .bat запускается и из Git Bash
```

`--analyze` — временная точка проверки ядра без GUI: сканирует папку или файл,
считает SHA-256, определяет форматы, читает текст (UTF-8/UTF-16/GBK), перечисляет
содержимое ZIP/APK и сохраняет отчёт в `%LOCALAPPDATA%\CHINA_AUTO_RUS\reports\`.

## Интерфейс

Запуск без аргументов открывает окно:

- «Открыть файл…» / «Открыть папку…» или drag & drop;
- вкладка **Файлы** — путь, размер, формат, SHA-256;
- вкладка **Дерево** — структура каталогов;
- вкладка **Ошибки** — файлы, которые не удалось прочитать;
- справа — предпросмотр: кодировка, текст, содержимое ZIP/APK;
- «Сохранить отчёт» — JSON + Markdown в `%LOCALAPPDATA%\CHINA_AUTO_RUS\reports\`;
- «Отмена» останавливает анализ после текущего файла;
- чекбокс `SHA-256` можно снять для быстрого прохода по большим дампам.

Анализ выполняется в `QThread`, поэтому окно не зависает.

## Диагностика

Необработанные исключения пишутся с traceback в
`%LOCALAPPDATA%\CHINA_AUTO_RUS\logs\app.log`. Пользователь видит понятное
сообщение, а не техническую трассировку. При запуске через `pythonw.exe`
консольный обработчик не создаётся. Содержимое анализируемых файлов в лог
не записывается.

## Безопасность

- Исходные файлы открываются **только на чтение** и не изменяются.
- Никаких подключений к электронным блокам автомобиля.
- Прошивки не записываются, защита производителя не обходится.
- Образы прошивок и бинарные артефакты не коммитятся в git.
- Неизвестные форматы не модифицируются вслепую.
- Логи ГУ содержат VIN, TUID, ICCID и приватный ключ. Каталог `dump/`
  в `.gitignore`, наружу такие файлы не передаются.

## Рабочий цикл

```bash
# 1. Разведка: что вообще лежит в дампе/APK
python -m china_auto_rus --analyze "C:\dump"

# 2. Все строки с языками — посмотреть объём
python -m china_auto_rus --resources "C:\dump\app.apk" --csv all.csv

# 3. Шаблон для переводчика: только уникальные строки на китайском
python -m china_auto_rus --resources "C:\dump\app.apk" --translation-csv ru.csv

# 4. Заполнить колонку translation (Excel/LibreOffice), сохранить UTF-8

# 5. Проверка: плейсхолдеры, теги, прогресс
python -m china_auto_rus --check-translations ru.csv
```

Шаг 5 возвращает `0`, только если ошибок нет: это условие для будущей
сборки. Оригиналы не меняются на всех шагах.

## Проверка writer'а ARSC

Перед сборкой APK полезно прогнать таблицу через пересборку:

```bat
.venv\Scripts\python.exe tools\check_arsc.py "dump\app.apk"
```

Скрипт только читает: разбирает `resources.arsc`, собирает обратно, сравнивает
модель и пробует заменить пару строк. `пересборка: байт-в-байт` — идеальный
результат. Если пишет `РАСХОДИТСЯ`, собирать APK нельзя.
