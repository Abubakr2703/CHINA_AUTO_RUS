# План русификации ГУ Deepal S07 2026

Документ описывает только исследование и подготовку. Запись в ГУ, прошивки
и работа с блоками автомобиля сюда не входят.

## Принципы

1. Оригиналы не изменяются. Любая правка делается на копии.
2. Сначала читаем и проверяем, потом собираем, потом ставим.
3. Один изменяемый пакет за раз. Не «весь `/system` сразу».
4. Перед установкой — копия оригинального APK и известный способ отката.
5. Не трогаем ECU, MCU, `ro.hardware.ecu.config.*`, сертификаты и загрузчик.
6. Не обходим защиту производителя: если пакет подписан и не ставится —
   это ответ, а не препятствие, которое надо ломать.

## Три технических пути

| Путь | Суть | Риск | Откат |
|---|---|---|---|
| **RRO-оверлей** | отдельный APK с ресурсами, оригинал не меняется | низкий | отключить/удалить оверлей |
| Правка `resources.arsc` | пересобрать APK с русскими строками | средний | вернуть оригинальный APK |
| Замена APK целиком | собрать новый APK с кодом | высокий | только при наличии копии и доступа |

Приоритет: RRO → правка ARSC → замена. RRO предпочтителен, потому что
оригинальный файл остаётся нетронутым, а откат не требует переустановки.

Ограничение: RRO работает, только если целевое приложение читает ресурсы
через `Resources` и не кэширует строки. Это проверяется на живом APK.

## Ключевое ограничение: подпись и установка

Все вендорские пакеты на этом ГУ — системные: они лежат в `/system`,
`/system/product`, `/vendor`, `/odm` или `/oem`. Для системных пакетов
действуют два правила Android, которые нельзя обойти настройками:

1. **Обновление пакета проверяет подпись.** APK, пересобранный и подписанный
   другим ключом, не установится поверх существующего пакета
   (`INSTALL_FAILED_UPDATE_INCOMPATIBLE`).
2. **Пользовательский RRO не может накрыть системное приложение**, если оно
   подписано ключом производителя. Статический RRO требует записи в
   `/vendor` или `/system`, а запись закрыта: SELinux в enforcing, root нет.

Отсюда следует, что все три пути упираются в один неизвестный фактор:
**проверяет ли установщик этого ГУ подпись**. Пока ответа нет, ни один путь
нельзя считать рабочим.

Проверять это надо двумя безопасными опытами, не трогая системные пакеты:

| Опыт | Что делаем | Что означает результат |
|---|---|---|
| 1 | поставить безобидный APK с **новым** именем пакета (F-Droid) | установка прошла → ставит сторонние APK; не прошла → канал закрыт |
| 2 | поставить **ту же** программу, переподписанную своим ключом | `INSTALL_FAILED_UPDATE_INCOMPATIBLE` → подпись проверяется |

Опыт 2 делается на F-Droid, а не на приложении из магазина: вендорские
пакеты не участвуют, откат — обычное удаление. Переподпись готовит
`tools/prepare_experiment.py` (снимает подпись v1, `zipalign`, `apksigner`).
Опыт 2 имеет смысл только после успешного опыта 1.

Если подпись не проверяется (опыт 2 прошёл), тот же ключ используется для
сборок `--build-apk`.

### Подготовлено на этом ПК

| Что | Где |
|---|---|
| JDK 17 (нужен `sdkmanager`) | `C:\Android\jdk17` |
| SDK: platform-tools, build-tools 34.0.0, platforms;android-33 | `C:\Android` |
| Тестовый ключ: alias `test`, пароль `testpass` | `C:\Android\keys\test.jks` |
| Флешка: `apk\FDroid.apk`, `apk\FDroid-otherkey.apk`, `dump\` | `%LOCALAPPDATA%\CHINA_AUTO_RUS\usb` |

`apksigner`, `zipalign`, `aapt2`, `adb` добавлены в пользовательский `PATH`.
Проверка: `python -m china_auto_rus --check` → `APK-инструменты: все на месте`.

Ключ тестовый: только для опытов и локальных сборок. Для постоянных сборок
нужен свой ключ и свой пароль.

Переподпись APK:

```bat
.venv\Scripts\python.exe tools\prepare_experiment.py FDroid.apk ^
  --keystore C:\Android\keys\test.jks --alias test ^
  --storepass testpass --out FDroid-otherkey.apk
```

Проверено: `aapt2 compile` и `aapt2 link` собирают оверлей без предупреждений.
Строки лежат в `res/values/strings.xml`, а не в `values-ru`: `aapt2` выбрасывает
строки локали, у которых нет default-значения.

Если подпись проверяется (вероятный исход), честный вывод такой: без root,
без ADB и без канала обновлений производителя замена системных APK
невозможна. Тогда русификация ограничивается тем, что не является системным
пакетом, либо ждёт появления штатного канала. Ломать проверку подписи,
патчить `PackageManager` или получать root — это обход защиты
производителя, и в этот проект он не входит.

## Что нужно, чтобы начать

1. APK хотя бы одного пакета с ГУ. Кандидаты по полезности:
   `com.mega.carsettings`, `com.mega.media`, `com.mega.sceneblock`,
   `com.mega.btphone`, `com.mega.car`.
2. Понимание, как ставится и удаляется APK на этом ГУ, и проверяется ли
   подпись. Без этого сборка не имеет смысла.
3. Копия оригинального APK, снятая до любых экспериментов.

Формат `resources.arsc` уже проверен на реальных сторонних APK (F-Droid,
NewPipe): пересборка совпадает байт-в-байт. Но APK с ГУ всё равно нужен:
у него свой набор пакетов и, возможно, другая версия `aapt`.

## Конвейер

```
инвентаризация → извлечение строк → перевод → проверка → сборка → установка → проверка → откат
```

| Шаг | Инструмент | Условие перехода |
|---|---|---|
| Инвентаризация | `--analyze`, `--resources` | видно, какие пакеты и строки есть |
| Извлечение | `--resources --translation-csv` | шаблон без технических строк |
| Перевод | внешний редактор CSV | колонка `translation` заполнена |
| Проверка | `--check-translations` | код возврата 0 |
| Сборка | `--build-apk` или `--rro` | APK собирается и разбирается обратно |
| Установка | штатный установщик ГУ | приложение запускается |
| Проверка | экран ГУ | русский текст, нет «квадратов» |
| Откат | копия APK / отключение оверлея | ГУ возвращается в исходное состояние |

### Две сборки из одного шаблона

`--build-apk` переписывает `resources.arsc` внутри копии APK. Плюс: работает
и для строк внутри layout. Минус: подпись производителя сломана, установка
такого APK на ГУ под вопросом.

`--rro` готовит исходники оверлея (`AndroidManifest.xml` и
`res/values/strings.xml`). Плюс: оригинальный APK остаётся нетронутым.
Минус: оверлей не накроет системное приложение с подписью производителя,
а статический оверлей требует записи в `/vendor`, которая закрыта.
Компиляция и подпись — внешние `aapt2`, `zipalign`, `apksigner`.

Выбор между ними — по результатам двух безопасных экспериментов из раздела
про подпись.

Ограничение шаблона: он дедуплицирован по тексту, поэтому в оверлей попадает
одно имя ресурса на каждый уникальный текст. Если тот же текст встречается
под другими именами, они останутся китайскими. Для оверлея это приемлемо на
первом этапе; при необходимости шаблон можно расширить до всех ключей.

## Порядок перевода пакетов

1. **Настройки** `com.mega.carsettings` — максимальная польза, низкий риск.
2. **Медиа** `com.mega.media`, `com.kugou.android.auto` — частые экраны.
3. **Сценарии** `com.mega.sceneblock`, `com.mega.scenemode`.
4. **Телефон** `com.mega.btphone`.
5. **Лаунчер и HMI** `com.deepal.ivi.hmi.showcarmode`, `com.mega.car`.
6. **Системные диалоги** `com.android.systemui`, `com.android.settings`.

Начинать с системных диалогов не стоит: ошибка там заметна сразу и
затрагивает весь интерфейс.

## Что не переводим

- технические атрибуты (`android:id`, `layout_*`, `permission`, `path*`);
- имена пакетов, классов, MIME-типы;
- строки с плейсхолдерами без сохранения `%1$s`, `{0}`, `<b>`;
- названия брендов и моделей;
- строки, где перевод ломает раскладку (кнопки фиксированной ширины).

Фильтр уже реализован в `core/axml.py` и `core/translation.py`.

## Безопасность и откат

- Перед экспериментами: копия APK, скриншот текущего состояния, запись
  версии сборки.
- Не ставить APK из непроверенных источников, особенно «русификаторы»
  с форумов.
- Не менять `ro.hardware.ecu.config.*`, не нажимать `下线配置功能`,
  `证书导入功能`, `恢复出厂设置`.
- Признаки проблемы: приложение не запускается, ГУ уходит в перезагрузку,
  пропадает звук или камера. Тогда сразу откат, без повторных попыток.
- Гарантия отката есть только при наличии оригинального APK и способа его
  установить. Пока способ установки неизвестен, установку не начинаем.

## Установка и откат: чек-лист

Выполнять только после того, как известен штатный способ установки APK
на этом ГУ. До этого установку не начинать.

1. Снять оригинальный APK с ГУ и сохранить копию вне ГУ.
2. Собрать APK с переводом:
   `--build-apk app.apk --translations ru.csv --output app-ru.apk`.
3. Выровнять и подписать своим ключом:

   ```bat
   zipalign -p 4 app-ru.apk app-ru-aligned.apk
   apksigner sign --ks my.jks --out app-ru-signed.apk app-ru-aligned.apk
   apksigner verify --print-certs app-ru-signed.apk
   ```

   Наличие `java`, `apksigner`, `zipalign`, `aapt2` показывает
   `python -m china_auto_rus --check`.
4. Установить через штатный канал (`应用商城`, USB или ADB, если включится).
5. Проверить на ГУ: запуск приложения, русский текст, нет «квадратов»,
   работают звук, камера, кнопки руля.
6. При любой проблеме — вернуть оригинальный APK тем же каналом, без
   повторных экспериментов.
7. Если установка отклонена из-за подписи — записать код ошибки
   (`INSTALL_FAILED_UPDATE_INCOMPATIBLE` и подобные) и остановиться:
   дальше нужен канал производителя, а не обход проверки.

## Открытые вопросы

| Вопрос | Статус |
|---|---|
| Как устанавливается APK | открыт: ADB выключен (`init.svc.adbd=stopped`), остаётся `应用商城` и USB-режим |
| Проверяется ли подпись | **главный вопрос**, проверяется опытом 2 выше |
| Читается ли `/system` без root | косвенно да: `日志管理` читает системные каталоги; запись закрыта (SELinux enforcing) |
| Поддерживает ли прошивка RRO | открыт: нужен живой APK и проверка активации оверлея |
| Штатное удаление пакета | открыт: `应用商城` умеет ставить, про удаление данных нет |
| Есть ли root | следов в логах нет, `su` и `magisk` не встречаются |
