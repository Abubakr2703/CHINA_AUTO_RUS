## 1. Подтверждённые ошибки

### P1. Отчёты перезаписывают друг друга в пределах одной секунды
`core/report.py:157`

```python
name = stem or f"report-{report.generated_at:%Y%m%d-%H%M%S}"
```

Два сохранения в одну секунду дают одинаковое имя. Второй файл молча затирает первый. В UI это легко воспроизвести: нажать «Сохранить отчёт» дважды.

### P1. Кодировка cp1251 определяется как GBK
`core/extractors.py:31-43`

Проверил на байтах `CF F0 E8 E2 E5 F2` (это «Привет» в cp1251): UTF-8 падает, GBK успешно декодирует. Для проекта, который делает **русскую** локализацию, это реальный риск: русский текст в cp1251 будет показан как китайские иероглифы и помечен `gbk`. Нужна либо эвристика по частоте символов, либо явное ограничение «GBK только для файлов с китайским контекстом».

### P1. Нет ограничения на количество файлов и общий объём
`core/scanner.py:178-241`

Есть `max_depth`, но нет:

- `max_files`;
- `max_total_bytes`;
- лимита на число ошибок;
- лимита на размер очереди/списка.

При выборе большой папки `result.files` растёт безгранично, затем копируется в `AnalysisReport`, в `FileTableModel`, в `QStandardItemModel` дерева и в JSON. На миллионе файлов это гарантированная проблема с памятью. Для инструмента, который будут запускать на дампах прошивок, это одна из главных дыр.

### P1. Отмена не прерывает хеширование одного большого файла
`core/scanner.py:34-40`

```python
while chunk := stream.read(chunk_size):
    digest.update(chunk)
```

`should_cancel` проверяется только между файлами. Если выбран образ на 50 ГБ, кнопка «Отмена» не сработает до конца хеширования. `closeEvent` ждёт 5 секунд и отказывает в закрытии (`ui/main_window.py:467`). Пользователь оказывается заблокирован.

То же касается `zipfile.infolist()` и сортировки огромного каталога: отмена внутри этих операций не проверяется.

### P2. Гонка после завершения анализа: клик «Открыть» может быть проигнорирован
`ui/main_window.py:236`, `280-313`, `428-433`

`_display_report()` вызывает `_set_busy(False)` и включает кнопки, но `self._thread` обнуляется только в `_on_thread_finished`. В этом окне `_start_analysis` видит `self._thread is not None` и молча возвращает управление. Клик по «Открыть папку» ничего не делает.

Лечится проверкой `isRunning()` или переносом разблокировки в `_on_thread_finished`.

### P2. `FileKind.BINARY` недостижим
`core/models.py:23`, `core/scanner.py:73`

`detect_kind` возвращает `UNKNOWN` для любого нетекстового файла, `BINARY` не возвращается нигде. В отчёте бинарники выглядят как `unknown`, хотя для них есть отдельный тип. Либо реализовать возврат `BINARY`, либо убрать enum.

### P2. Ложное «предпросмотр обрезан» для файла ровно 64 КБ
`core/extractors.py:56`

```python
truncated = len(raw) == sample_size or len(text) > limit
```

Файл размером ровно `SAMPLE_SIZE` читается целиком, но помечается обрезанным. Нужно `len(raw) == sample_size and file_size > sample_size` или проверять ещё один байт.

### P2. `base_dir` и относительные пути ломаются при выборе файлов с разных дисков
`core/scanner.py:132-137`

`os.path.commonpath` для `C:\...` и `D:\...` бросает `ValueError`, код берёт первый anchor. Для файлов на другом диске `_relative` падает в `ValueError` и возвращает абсолютный путь. В отчёте получается смесь относительных и абсолютных путей при одном `base_dir`.

### P3. Дублирование версии и мёртвый `APP_VERSION`
`config.py:9`, `__init__.py:3`, `pyproject.toml:7`

Три источника версии: `APP_VERSION`, `__version__`, `pyproject`. `APP_VERSION` нигде не используется. Рано или поздно разъедутся. Лучше `importlib.metadata.version("china-auto-rus")`.

### P3. Необработанные ошибки в мелких путях
- `ui/main_window.py:416` — `REPORTS_DIR.mkdir()` без `try`, падение слота при отсутствии прав.
- `__main__.py:56-57` — `save_report()` без `try`, при недоступном `workspace/` будет traceback вместо понятного сообщения.
- `logging_setup.py:17-18` — если корневой логгер уже имеет обработчики, файловый лог молча не создаётся.
- `ui/__init__.py:1` — устаревший docstring «Реализация — Этап 2».

## 2. Потенциальные проблемы

### Память и масштабирование
- Нет `max_files`/`max_total_bytes`; `result.files`, `errors`, `insights` не ограничены.
- `FileTableModel.set_report` копирует список файлов, хотя отчёт уже хранит его.
- `build_tree_model` создаёт `QStandardItem` на каждый компонент пути — на больших деревьях это тяжело.
- `report_to_dict` и `render_markdown` строят отчёт целиком в памяти.
- `list_archive` вызывает `infolist()` и затем строит `set` всех имён, даже если `max_entries=2000`. ZIP с миллионами записей или именами по 60 КБ — это memory/CPU DoS ещё до срезания списка.
- Имена записей архива не ограничены по длине и попадают в UI/JSON/Markdown. 300 длинных имён в предпросмотре могут дать десятки мегабайт текста.

### ZIP/APK
- Классическая zip-бомба не срабатывает: данные не распаковываются, читается только central directory. Это правильно.
- Но central directory bomb, огромное число записей, ZIP64 и длинные имена не ограничены.
- `zipfile` на некоторых повреждённых архивах может бросить исключение вне текущего списка (`struct.error`, `OverflowError`). `analyzer.py:61` ловит только `OSError`, `BadZipFile`, `ValueError`. Тогда `worker` ловит всё и обрывает **весь** анализ, теряя уже собранные результаты. Лучше ловить `Exception` на уровне одного файла и продолжать.
- Зашифрованные ZIP: листинг работает, но дальнейшее извлечение — нет; сейчас это не мешает.
- Пути `../` в архиве безопасны, потому что распаковки нет. Но они попадают в отчёт/UI как есть.
- `.apks`, `.xapk`, APK без расширения определяются как `ZIP`, а не `APK`. Семантика APK завязана на расширение, а не на наличие `AndroidManifest.xml`.

### Кодировки
- GB18030 не поддерживается: 4-байтовые последовательности упадут в fallback UTF-8 с `�`.
- UTF-16 без BOM определяется как `UNKNOWN`, потому что `_is_text_like` видит NUL.
- UTF-32/Big5 не поддерживаются.
- Пустой файл получает `UNKNOWN`, а не `TEXT`.
- Обрезка сэмпла может разрезать многобайтовый символ — в предпросмотре появится `�`.
- Нет оценки уверенности: GBK и cp1251 пересекаются.

### Форматы
- XML определяется по расширению или `<?xml`, JSON — только по расширению. Текстовый `foo.json` с мусором будет помечен `json`; `foo.xml` с обычным текстом — `xml`.
- Нет BMP, WEBP, TIFF, HEIC/AVIF, self-extracting ZIP, ODEX.
- Бинарный файл без NUL и с малым числом control-байт может быть принят за текст.
- `HEAD_SIZE=4096` достаточно для сигнатур, но ZIP с самораспаковывающимся stub не распознается.

### Отчёты
- Имя файла с точностью до секунды → перезапись (см. выше).
- Запись JSON и Markdown неатомарна: при сбое/заполнении диска останется частичный файл.
- Нет `schema_version`; потребителю отчёта не на что опереться при изменении формата.
- В отчёте только `profile_id`, без brand/model/year. Для внешнего анализа этого мало.
- `generated_at` — naive local time без таймзоны.
- `stem` не санитизируется: если позже появится «Сохранить как…», возможен path traversal.
- Markdown экранирует `|` и переводы строк, но не control-символы из имён архива.
- `human_size` для >1 ТБ остаётся в ТБ (2 ПБ → «2048.0 ТБ»), но это косметика.

### QThread и отмена
- `worker.cancel()` — обычный `bool`, а не `threading.Event`. В CPython это работает, но семантика памяти неявная.
- `worker.deleteLater()` вызывается из GUI-потока после остановки event loop воркера (`main_window.py:294-300`). Это может не выполниться: событие отложенного удаления уйдёт в уже остановленный цикл. Стандартный паттерн — `worker.finished → worker.deleteLater` и `thread.finished → thread.deleteLater`.
- Отмена проверяется между файлами, но не внутри `sha256_file`, `infolist`, `sorted(scandir)`.
- `progress` эмитится на каждый файл без троттлинга; на сотнях тысяч файлов очередь событий GUI может захлебнуться.
- `closeEvent` с `wait(5000)` блокирует GUI и может не дать закрыть приложение.
- Нет `sys.excepthook` для GUI: исключение в слоте Qt может не попасть в `logs/app.log`.

### Логирование и развёртывание
- `PROJECT_ROOT = Path(__file__).resolve().parents[2]` работает в editable-режиме, но при установке wheel в `site-packages` `workspace/` и `logs/` окажутся в каталоге Python, а при PyInstaller — во временном `_MEI`. Для Windows-приложения данные должны жить в `%LOCALAPPDATA%\CHINA_AUTO_RUS`.
- Если каталог проекта только для чтения, `ensure_directories()`/`RotatingFileHandler` уронят запуск.
- При запуске через `pythonw` `sys.stderr` может быть `None`, а `StreamHandler` создаётся без явного потока.
- Логи не фиксируют параметры скана (пути, `compute_hashes`, лимиты), что затрудняет разбор инцидентов.

### Продуктовые пробелы
- «Импорт файлов и папок» реализован как анализ **на месте**, без копирования в `workspace/`. Если под импортом подразумевалось копирование, функция не сделана.
- «Сохранение оригинальных файлов» как backup не реализовано; оригиналы просто не изменяются.
- Нет анализа `.img`/`.bin`/`.upd`/кастомных контейнеров прошивок — только размер, хеш и `UNKNOWN`.
- Нет hex-просмотра и извлечения строк из ELF/бинарников — для исследования мультимедиа это было бы полезно.

## 3. Android-допущения (отдельно)

**Явного «Deepal S07 работает на Android» в коде нет.** Это хорошо:

- `config.DEFAULT_PROFILE` оставляет `head_unit=None` и `hardware_platform=None`;
- `AGENTS.md` прямо запрещает выдумывать платформу;
- сканер определяет форматы generic-способом.

**Но косвенная Android-ориентация есть:**

- `FileKind.APK`, `FileKind.DEX`, магия `dex\n`;
- в `extractors.py:83-86` жёстко зашиты `resources.arsc` и `AndroidManifest.xml`;
- в `extractors.py:111-112` для любого `.apk` пишется «языковые строки в resources.arsc/AXML — Этап 3»;
- README и план Этапа 3 говорят про AXML/ARSC;
- `.apk` определяется по расширению, без проверки `AndroidManifest.xml`.

Риск: если ГУ S07 окажется на QNX/Linux/кастомной RTOS, весь план Этапа 3 уйдёт не туда. До реализации парсеров нужно подтвердить платформу по реальному дампу. Android-парсеры стоит держать за детектором формата, а не делать их единственным путём. Формулировки в UI/README лучше сделать условными: «если это Android APK».

## 4. Недостающие тесты

**Безопасность сканера:**
- лимит глубины (`max_depth`);
- отсутствие `max_files`/`max_total_bytes` — тест должен зафиксировать текущее поведение или будущий лимит;
- symlink/junction (на Windows — junction через `mklink /J`, не требует админа);
- symlink, переданный как корень;
- permission denied на файл и на каталог;
- файл исчез/изменился между `stat` и чтением;
- пути с кириллицей, китайскими символами, пробелами, `|`, переводами строк;
- длинные пути >260 символов;
- дубликаты путей в разном написании (`..`, относительный/абсолютный);
- файлы с разных дисков.

**SHA-256 и большие файлы:**
- хеш файла больше одного chunk;
- отмена во время хеширования (после реализации);
- `compute_hashes=False` на уровне `analyze_paths`/отчёта.

**ZIP/APK:**
- ZIP с 0 записей;
- ZIP с дублирующимися именами;
- зашифрованный ZIP;
- ZIP64;
- очень длинные имена записей;
- архив с `../` и абсолютными путями;
- повреждённый central directory (не только обрезанный `PK\x03\x04`);
- APK с `AndroidManifest.xml`/`resources.arsc` и без них;
- `.apks`/`.xapk`/APK без расширения;
- несколько архивов, один битый — анализ должен продолжиться.

**Кодировки:**
- UTF-8 BOM;
- UTF-16 LE/BE без BOM;
- GB18030;
- cp1251 (ожидаемое поведение зафиксировать);
- пустой файл;
- сэмпл, обрезанный посреди многобайтового символа;
- файл ровно `SAMPLE_SIZE`.

**Отчёты:**
- два сохранения в одну секунду;
- ошибка записи (read-only каталог);
- полная схема JSON (все поля, errors, insights, archive_entries);
- экранирование `|`, переводов строк, control-символов;
- кириллица/китайский в JSON и Markdown;
- отчёт по пустому скану и по отменённому скану.

**UI/QThread:**
- отмена во время анализа (частичный отчёт);
- `failed`-путь worker;
- очистка `_worker`/`_thread` после завершения;
- клик «Открыть» сразу после завершения (гонка);
- закрытие окна во время анализа;
- сохранение отчёта из UI;
- содержимое вкладки «Ошибки»;
- отсутствие импортов PySide6 в `core` (архитектурный тест).

## 6. Что уже сделано правильно

- **Чёткое разделение core/ui.** `core` не импортирует PySide6, логика тестируется без GUI.
- **Read-only по умолчанию.** В `core` нет записи в исходники; отчёты идут только в `workspace/reports`.
- **Потоковое чтение.** SHA-256 считается чанками по 1 МБ, для определения формата читается 4 КБ, текст — 64 КБ. Файлы не загружаются целиком.
- **ZIP без распаковки.** Читается только central directory; классическая zip-бомба не срабатывает.
- **Защита обхода.** Symlink/junction пропускаются для элементов дерева, есть лимит глубины.
- **Отмена и прогресс.** Флаг отмены, callback прогресса, `QThread`-worker, UI не зависает.
- **Ошибки не теряются.** Собираются в `ScanError`, логируются, показываются во вкладке и попадают в отчёт.
- **Форматы по magic bytes** для ZIP/ELF/DEX/SQLite/PNG/JPEG/GIF; расширение используется только как уточнение.
- **Кодировки без внешних зависимостей:** UTF-8, UTF-16 по BOM, GBK, fallback с `errors="replace"`.
- **Отчёты:** JSON с `ensure_ascii=False`, UTF-8, Markdown с экранированием таблиц и ограничением предпросмотра.
- **Тесты:** 30 зелёных, включая end-to-end, read-only-проверку по SHA-256, битый ZIP, отмену и реальный `QThread`.
- **Профиль автомобиля честный:** неизвестные характеристики остаются `None`, ничего не выдумано.
- **`.gitignore`** исключает прошивки, образы, `workspace/`, `logs/` и `.venv`.
